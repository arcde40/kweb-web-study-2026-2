# 방명록 서비스 API 명세

## 1. 개요

누구나 글을 남기고 볼 수 있는 간단한 방명록 서비스입니다.
로그인은 없고, 글을 쓸 때 정한 비밀번호로 수정/삭제 권한을 확인합니다.

- 리소스: `entries` (방명록 글 하나)
- 데이터 형식: 요청/응답 모두 JSON (`Content-Type: application/json`)
- 경로 규칙: 명사, 소문자, 하이픈 사용, 끝에 `/` 없음, 확장자 없음, URI에 동사 없음

## 2. 데이터 모델

### Entry

| 필드 | 타입 | 설명 |
|------|------|------|
| id | number | 글 번호 (서버가 부여) |
| name | string | 작성자 이름, 1~20자 |
| message | string | 내용, 1~500자 |
| createdAt | string | 작성 시각 (ISO 8601) |
| updatedAt | string | 마지막 수정 시각 (ISO 8601) |

- `password`는 요청에서만 받고(4~20자), 서버에는 해시로 저장합니다. 응답에는 절대 포함하지 않습니다.
- 앞뒤 공백은 제거한 뒤 길이를 검사합니다.

## 3. 명세표

| 메서드 | 경로 | 설명 | 성공 | 실패 |
|--------|------|------|------|------|
| GET | `/entries` | 글 목록 조회 | 200 | 400 (잘못된 쿼리) |
| POST | `/entries` | 글 작성 | 201 | 400 (검증 실패) |
| GET | `/entries/:id` | 글 하나 조회 | 200 | 404 |
| PUT | `/entries/:id` | 글 수정 | 200 | 400, 403, 404 |
| DELETE | `/entries/:id` | 글 삭제 | 204 | 400, 403, 404 |
| 그 외 | `*` | 정의되지 않은 메서드 | - | 405 + `Allow` 헤더 |

정의되지 않은 경로는 404, 정의된 경로에 허용되지 않은 메서드는 405입니다.

## 4. 상세

### GET /entries

글 목록을 최신순으로 반환합니다.

쿼리

| 이름 | 기본값 | 설명 |
|------|--------|------|
| page | 1 | 페이지 번호 (1 이상의 정수) |
| limit | 10 | 페이지당 글 수 (1~50) |

응답 200

```json
{
  "entries": [
    {
      "id": 2,
      "name": "정훈",
      "message": "안녕하세요!",
      "createdAt": "2026-11-14T10:00:00.000Z",
      "updatedAt": "2026-11-14T10:00:00.000Z"
    }
  ],
  "page": 1,
  "limit": 10,
  "total": 2
}
```

### POST /entries

요청 본문

```json
{ "name": "정훈", "message": "안녕하세요!", "password": "1234" }
```

- 성공: 201, 생성된 Entry 반환, `Location: /entries/{id}` 헤더 포함
- 실패: 400, name/message/password 중 하나라도 비었거나 길이 제한을 넘은 경우

### GET /entries/:id

- 성공: 200, Entry 반환
- 실패: 404, 해당 id의 글이 없는 경우
- `id`가 숫자가 아니면(`/entries/abc`) 404로 처리합니다.

### PUT /entries/:id

글 전체를 교체합니다. `name`, `message`를 모두 보내야 합니다.

요청 본문

```json
{ "name": "정훈", "message": "수정한 내용", "password": "1234" }
```

- 성공: 200, 수정된 Entry 반환 (`updatedAt` 갱신)
- 실패
  - 400: name/message 검증 실패
  - 403: 비밀번호 불일치
  - 404: 글이 없음

### DELETE /entries/:id

요청 본문

```json
{ "password": "1234" }
```

- 성공: 204, 본문 없음
- 실패
  - 403: 비밀번호 불일치
  - 404: 글이 없음

## 5. 에러 응답 형식

모든 에러는 같은 형식으로 반환합니다.

```json
{ "error": "메시지가 비어 있습니다." }
```

## 6. 결정 사항과 이유

- 수정/삭제에 비밀번호를 쓴 이유: 로그인 기능 없이 최소한의 권한 확인만 하기 위해서입니다.
- 비밀번호를 본문으로 받는 이유: 쿼리스트링에 넣으면 주소창, 서버 로그에 남을 수 있습니다.
- 목록을 최신순으로 한 이유: 방명록은 새 글을 먼저 보는 경우가 대부분입니다.
- PUT을 쓴 이유: 수업 컨벤션(GET 조회 / POST 생성 / PUT 수정 / DELETE 삭제)을 따랐습니다.

## 7. 이번 범위에서 제외

- 로그인, 회원가입
- 댓글, 답글
- 검색, 필터
- 스팸 방지 (rate limit 등)
