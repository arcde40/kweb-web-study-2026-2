## 방명록 서비스 API 명세

### 1. 서비스 소개
- 방문자가 이름과 짧은 메시지를 남기고, 다른 방문자의 글을 읽을 수 있는 서비스이다.
- 회원가입과 로그인 없이 누구나 글을 작성하고 조회할 수 있다.
- 글을 작성할 때 비밀번호를 설정한다. 해당 비밀번호를 입력하면 글을 수정하거나 삭제할 수 있다.

### 2. 제공할 기능
- 방명록 글 작성
- 방명록 글 목록 조회
- 비밀번호 확인 후 작성자 이름과 글 내용 수정
- 비밀번호 확인 후 글 삭제

### 3. 방명록 글의 정보
- `id`: 글을 구분하는 고유 번호. 서버에서 부여한다.
- `name`: 작성자 이름
- `content`: 글 내용
- `passwordHash`: 비밀번호를 해시 처리한 값. 서버에서 보관하며 API 응답에 포함하지 않는다.
- `createdAt`: 작성 시각. 서버에서 기록한다.
- `updatedAt`: 마지막 수정 시각. 처음에는 작성 시각과 같으며, 수정할 때 서버에서 갱신한다.
- 시각은 ISO 8601 형식의 UTC 문자열로 표현한다. 예: `"2026-10-31T12:00:00.000Z"`

### 4. API 명세
- 요청과 응답 데이터는 JSON 형식을 사용한다.
- 글 정보 응답에는 `id`, `name`, `content`, `createdAt`, `updatedAt`만 포함한다.
- 비밀번호와 비밀번호 해시값은 모든 API 응답에서 제외한다.
- 실패 응답의 본문은 화면에 보여줄 수 있는 오류 메시지를 담는다.
  ```json
  { "error": "비밀번호가 일치하지 않습니다." }
  ```
- 서버 내부 오류가 발생하면 `500 Internal Server Error`를 반환한다.

#### 4.1. 방명록 글 작성
- 메서드와 경로: `POST /entries`
- 설명: 새로운 방명록 글을 저장한다.
- 요청 데이터:
  - `name`: 작성자 이름
  - `content`: 글 내용
  - `password`: 수정·삭제에 사용할 숫자 네 자리 비밀번호
- 요청 예시:
  ```json
  {
    "name": "이승우",
    "content": "방명록 남기고 갑니다!",
    "password": "0123"
  }
  ```
- 성공 응답: `201 Created`와 생성된 글 정보
- 응답 예시:
  ```json
  {
    "id": 1,
    "name": "이승우",
    "content": "방명록 남기고 갑니다!",
    "createdAt": "2026-10-31T12:00:00.000Z",
    "updatedAt": "2026-10-31T12:00:00.000Z"
  }
  ```
- 실패 응답: 필수 데이터가 없거나 입력 규칙을 위반하면 `400 Bad Request`

#### 4.2. 방명록 글 목록 조회
- 메서드와 경로: `GET /entries`
- 설명: 저장된 방명록 글 목록을 조회한다.
- 쿼리 파라미터:
  - `sort`: 작성 시각 기준 정렬 순서. 선택 항목
    - `newest`: 최신 글부터 조회한다.
    - `oldest`: 오래된 글부터 조회한다.
  - `sort`를 생략하면 기본값으로 `newest`를 적용한다.
- 요청 예시:
  - `GET /entries`: 최신순 조회
  - `GET /entries?sort=newest`: 최신순 조회
  - `GET /entries?sort=oldest`: 오래된순 조회
- 성공 응답: `200 OK`와 선택한 순서로 정렬된 글 정보의 배열
- 글이 없는 경우: `200 OK`와 빈 배열 `[]`을 반환한다.
- 실패 응답: `sort`에 `newest`, `oldest` 이외의 값을 보내면 `400 Bad Request`

#### 4.3. 방명록 글 수정
- 메서드와 경로: `PATCH /entries/:id`
- 설명: 비밀번호를 확인한 뒤 해당 글의 작성자 이름 또는 내용을 수정한다.
- 경로의 `id`: 수정할 글의 고유 번호
- 요청 데이터:
  - `name`: 변경할 작성자 이름. 선택 항목
  - `content`: 변경할 글 내용. 선택 항목
  - `password`: 글 작성 시 설정한 숫자 네 자리 비밀번호. 필수 항목
- 수정 규칙:
  - `name`과 `content` 중 하나 이상을 보내야 한다.
  - 보내지 않은 항목은 기존 값을 유지한다.
  - 변경할 이름과 내용에도 기존 입력 규칙을 적용한다.
  - 비밀번호는 변경하지 않는다.
  - 수정에 성공하면 서버가 `updatedAt`을 갱신한다.
- 성공 응답: `200 OK`와 수정된 글 정보
- 실패 응답:
  - 글 번호 형식이 잘못되거나 요청 데이터가 입력 규칙을 위반하면 `400 Bad Request`
  - 해당 글이 없으면 `404 Not Found`
  - 비밀번호가 일치하지 않으면 `403 Forbidden`
  - 비밀번호 확인 요청 횟수를 초과하면 `429 Too Many Requests`

#### 4.4. 방명록 글 삭제
- 메서드와 경로: `DELETE /entries/:id`
- 설명: 비밀번호를 확인한 뒤 해당 글을 삭제한다.
- 경로의 `id`: 삭제할 글의 고유 번호
- 요청 데이터:
  - `password`: 글 작성 시 설정한 숫자 네 자리 비밀번호. 필수 항목
- 성공 응답: `204 No Content`. 응답 본문은 보내지 않는다.
- 실패 응답:
  - 글 번호 형식이 잘못되거나 요청 데이터가 입력 규칙을 위반하면 `400 Bad Request`
  - 해당 글이 없으면 `404 Not Found`
  - 비밀번호가 일치하지 않으면 `403 Forbidden`
  - 비밀번호 확인 요청 횟수를 초과하면 `429 Too Many Requests`
- 삭제된 글은 목록에서 제외하며, 이후 수정·삭제 요청에는 `404 Not Found`를 반환한다.

### 5. 입력 규칙
- 작성자 이름(`name`), 글 내용(`content`), 비밀번호(`password`)는 문자열이어야 한다.
- 작성자 이름은 앞뒤 공백을 제거한 뒤 1~20자로 제한한다.
- 글 내용은 앞뒤 공백을 제거한 뒤 1~500자로 제한한다.
- 공백만 입력한 이름이나 내용은 허용하지 않는다.
- 비밀번호는 `0`~`9`로 이루어진 정확히 네 자리 문자열이어야 한다.
- `"0123"`처럼 앞에 0이 있는 비밀번호도 허용한다.
- 비밀번호에는 공백을 허용하지 않으며, 앞뒤 공백을 자동으로 제거하지 않는다.
- 수정 요청에서 이름과 내용은 하나 이상 포함해야 하며, 보내지 않은 항목은 기존 값을 유지한다.
- 수정하는 이름과 내용에도 동일한 입력 규칙을 적용한다.
- 비밀번호는 수정할 수 없다.
- 글 번호(`id`)는 1 이상의 정수여야 한다.
- 비밀번호는 URL이나 쿼리 문자열에 넣지 않고 요청 본문으로 전달한다.
- 서버는 비밀번호를 평문으로 저장하지 않고, 비밀번호 저장용 해시 함수를 사용한다.
- 비밀번호와 비밀번호 해시값은 API 응답에 포함하지 않는다.

### 6. 비밀번호 확인 요청 횟수 제한
- 각 글에 대해 첫 비밀번호 확인 요청부터 1분 동안 최대 5회의 요청을 허용한다.
- 수정·삭제 요청은 동일한 횟수 제한을 공유한다.
- 비밀번호의 일치 여부와 관계없이 확인 요청을 횟수에 포함한다.
- 제한을 초과하면 `429 Too Many Requests`를 반환하며, 수정·삭제를 수행하지 않는다.
- 응답의 `Retry-After` 헤더에 다시 시도할 때까지 남은 시간을 초 단위로 안내한다.
- 첫 요청부터 1분이 지나면 횟수를 초기화한다. 차단 중 추가 요청을 보내도 대기 시간은 늘어나지 않는다.
- 요청 횟수 기록은 서버 메모리에 보관하며, 서버를 재시작하면 초기화된다.

### 7. 기술 스택
- 서버 실행 환경: Node.js
- 서버 프레임워크: Express.js — 글 작성·조회·수정·삭제 요청 처리
- 데이터 저장: JSON 파일(`data/entries.json`). 서버를 재시작해도 글이 유지된다.
- 화면 구성: HTML
- 화면 디자인: CSS
- 화면 동작 및 API 요청: JavaScript
- 역할별로 파일을 분리한다.
  - `server.js`: 서버 및 API 요청 처리
  - `index.html`: 화면 구성
  - `styles.css`: 화면 디자인
  - `app.js`: 화면 동작 및 서버와의 통신
